# Editorial conventions

These rules apply to people editing the design foundations specification. They do not apply to agents generating tokens.

- Use sentence case for headings, table headers, and prose.
- Use **bold** only for key terms and section-leading labels.
- Use inline code only for token-name patterns, HEX values, numeric formulas, and exact Figma values. Do not use inline code for token names inside tables.
- Write Figma interface labels, collection names, modes, themes, color spaces, and standards in plain text: Primitives, Theme, Appearance, Light, Dark, OKLCH, sRGB, WCAG.
- Use "section" when referring to another numbered section of the specification.
- Use "Note:" for explanatory notes, followed by a complete sentence.
- Keep one blank line before and after headings, tables, lists, and notes.
- Use tables for token lists, mappings, scopes, and validation rules.
- Use ordered lists only for sequential procedures. Use unordered lists for non-sequential rules.
